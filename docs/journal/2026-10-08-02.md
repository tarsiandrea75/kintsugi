# Journal — 2026-10-08 — Session 02: RAG on the runbooks

## What happened
- **runbook-rag** ([feature](../../odd/tasks/runbook-rag.md), [ADR-002](../adr/ADR-002-pgvector-knowledge-base.md), [spec](../../openspec/specs/knowledge-base/spec.md)) is the second M2 item.
  - A separate pgvector store holds the index.
  - A one-shot indexer reads only `docs/runbooks/` behind a leakage gate.
  - `search_runbooks` is the 8th mcp-tools tool.
  - A socat proxy lets containers reach the host's Ollama.
- **Research first.** It disproved two premises: the `vector` extension is not trusted, and the containers could not reach Ollama.
- **Human decisions:**
  - the embedding model, `nomic-embed-text`, chosen after learning that the model is configurable in code but the index is coupled to it;
  - the socat proxy, over `OLLAMA_HOST=0.0.0.0` and a containerised Ollama.
- **Reviews** ran on every range: 6 lineages, all approved. They caught:
  - a leakage pattern that matched "default";
  - a model guard that ignored the digest;
  - non-atomic re-indexing;
  - an oversized-chunk hole;
  - a half-initialized volume on a failed init;
  - passwords on the psql command line;
  - a chunkless file reprocessed on every run;
  - unproven Ollama timeouts;
  - a proxy bind failure that blocked the whole lab;
  - an unscoped `start_lab` fallback.

  Each was fixed in the following commit. The rest is recorded as follow-ups.
- **Live results:**
  - 51 chunks;
  - the right runbook first for payment-pending and slow-reservation symptoms;
  - the gateway runbook 2nd for a rate-limit query;
  - a model mismatch refused.

## Decisions and why
- **A separate knowledge store.** A fault injected into the lab's postgres must never cut the agent off from its runbooks.
- **The index is tied to the model.** Vectors from different models cannot be compared, so a mismatch is refused loudly instead of answered wrongly.
- **`JdbcTemplate` instead of `PgVectorStore`.** We need the document and query prefixes and a single transaction per run.
- **The proxy binds only to the Docker bridge.** Ollama stays on loopback, and the change lives in the repo, not in host configuration.
- **The evidence tools never depend on Ollama.** A failed indexer or proxy only disables `search_runbooks`.

## Process deviations

## Decisions and why

- **The rules enter the agent only as H's proposer (ADR-019).** Config 0 stays frozen at `5797d16`, so H − 0 measures what the model adds once it sees the rules.
- **No fallback to the rules' first candidate.** A fallback would mix the rules' answers into H's number. It can be computed afterwards from the paired rows.
- **The lab dev run is a mechanics check.** Dev was read many times. The stop rule names RCAEval dev, which needs the converter and topology-as-data first.

## What the numbers say

- **Overall:** H scored 13/15 on dev, 87% [62%, 96%]; Config 0 scored 10/15 and Qon 8/15.
  - H − 0: +20 points, Holm p = 0.91.
  - H − Qon: +33 points, Holm p = 0.19, with a bootstrap interval of [+13, +60].
  - No UNKNOWN and no invalid reports. Every sample took one report call, 675-1660 s.
- **F2 and F3:** each list held one candidate, the truth. The gain on these faults comes from the rules' proposals, not from the model's choice.
- **F1:** the only fault with a real choice.
  - The model kept the rules' first candidate 3 times out of 5.
  - Twice it picked the caller `payment-service`, which is Qon's own failure mode.
  - Taking the first candidate would have scored 15/15 on these cases.
- **What to test on RCAEval:** whether the model adds anything when the list has more than one entry.

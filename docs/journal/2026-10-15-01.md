## What happened
- **agent-loop T1–T4** built the incident API, the state store (Flyway), the MCP client with summarizers, and the phased loop with its plan and report checks.
- **T5** wired the agent into Compose and added `verify-agent.sh`, which runs F1–F3 for real with `granite4.1:8b` on CPU.
- **Eight full runs.** Each fix came from reading the stored incident steps of the previous run.

- **Reviews:** every code range was reviewed and approved. Their follow-ups are in the feature document and `docs/STATE.md`.

## Decisions and why
- **Fix deterministically, from evidence.** Each change follows the core rule: the LLM proposes, deterministic code verifies. The changes include refusals that cost no budget, quotes checked against what the model saw, and unverifiable evidence dropped rather than trusted.
- **Drop, don't reject (T5c11).** One non-verbatim quote no longer throws away a report whose other evidence is verified. Only verified items are stored and scored.
- **One sample per fault is noisy.** A replay harness over recorded tool outputs is proposed, but not yet approved.

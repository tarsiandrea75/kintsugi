# Journal — 2026-10-08 — Session 01: the MCP tools server (autonomous)

## What happened
- **Autonomous work.** The human authorized working alone until the quota ran out. Design decisions taken without the human are marked "to review" in the [feature document](../../odd/tasks/mcp-tools.md) and in [ADR-004](../adr/ADR-004-tools-via-mcp.md).
- **mcp-tools** is the first M2 item. It is an MCP server over STATELESS Streamable HTTP, bound to loopback, that exposes 7 read-only tools on Loki, Prometheus and the event tables. It was built in five tasks: ADR and spec, skeleton, observability tools, evidence tools with the `kintsugi_agent` role, and compose wiring with `verify-mcp.sh`. The chain is `feat/mcp-tools` → `-01-observability-tools` → `-02-evidence-tools` → `-03-wiring`.
- **Reviews** were run on every committed range: 6 lineages, all approved. They caught:
  - the Spring AI default of a no-op Origin validator;
  - a case-sensitive protocol guard;
  - an 8 KB cap that returned OK with no data;
  - every connection failure being labelled "unreachable";
  - event domains duplicated between validation and tool descriptions;
  - a verify script that wiped the lab volume on a transient probe failure.

  Each was fixed in the following commit. What was not fixed is recorded as a follow-up.
- **Checks:**
  - mcp-tools: 140 tests;
  - `verify-mcp.sh` passes on a fresh volume and on reruns;
  - `verify-f1.sh` … `verify-f4.sh` still pass.

## Decisions and why
- **Templates only, no free query language.** A small model cannot be trusted with SQL, LogQL or PromQL, and a template plus enum validation makes reaching `faults` or `fault-injector` impossible rather than merely forbidden.
- **STATELESS transport, loopback port, Origin and Host validation.** The tools need no server-to-client messages. The defaults of Spring AI 2.0.1 validate nothing, so the transport bean is ours.
- **An event trigger grants SELECT to `kintsugi_agent`, instead of default privileges.** Default privileges would also expose `order_items`, `flyway_schema_history` and every future table. Only the six evidence tables are needed.
- **The database health check is disabled.** A PostgreSQL outage is evidence the tools report, not a reason to mark mcp-tools DOWN.
- **No p95.** The lab exports no latency histogram, so the tools offer the average and the maximum.

# Journal — 2026-10-05 — Session 02: Spring AI hello-world

## What happened
- Pushed the bootstrap to a private GitHub repository using the corporate git identity.
- Verified the environment: Corretto Java 21.0.9, Ollama 0.34.4, Python 3.14.0; Maven 3.8.9 is replaced by the Maven Wrapper (3.9.16); Docker is not installed yet.
- Pulled `granite4.1:8b` and built the first code through the SDD change `spring-ai-hello-tool`: Spring Boot 4.1.1 + Spring AI 2.0.1 skeleton, `TimeTools.currentTime(zone)` with an injected `Clock`, a tool-enabled `ChatClient`, a `demo`-profile runner and a `live` test.
- Result: with the clock fixed at 12:00Z, the model called the tool and answered "09:00" for Buenos Aires in about 33 s on CPU. 14 offline tests run without Ollama.
- Archived both SDD changes; their specs are now the current specs in `openspec/specs/`.

## Decisions and why
- **Split hello-world (A) from the model smoke test (B).** Why: one change would exceed the 400-line review budget; A alone already meets the week-1 Monday goal.
- **ADR-006 for stack versions.** Why: the vision reserves ADR-002 to ADR-005; the model choice goes to ADR-003 after change B.
- **No `ModelRouter` yet.** Why: YAGNI until a second provider exists (M2); Spring AI types stay in `tools/`, `config/` and `demo/`. Accepted deviation from the vision, which says the agent never calls a model directly.
- **The tool returns an error string instead of throwing.** Why: an error is an observation the model can recover from; an exception breaks the loop.
- **Demo only under the `demo` profile; fails fast when Ollama is down.** Why: tests must never call the model by accident, and a clear message beats a stack trace.
- **`spring.ai.retry.max-attempts: 0`.** Why: the default retries a refused connection 10 times with backoff up to 180 s; on localhost a refused connection means the server is down.
- **Strict live assertion (exact `HH:mm` from a fixed clock).** Why: a fixed clock turns non-deterministic model output into something code can check.
- **Size exception accepted (~442 hand-written code lines).** Why: most of the overrun is tests; trimming tests to fit a number would optimize the metric, not the goal.
- **Two resets of the SDD attempt ledger.** Why: the per-unit budget counted Initializr-generated files and approved planning artifacts as changed lines. Next time, generated files and planning artifacts go in commits separate from code.
- **Live test never observed RED.** Accepted TDD deviation: the production code already existed; recorded in the apply progress.

# Journal — 2026-10-05 — Session 03: Model smoke test (change B)

## What happened
- Found no active SDD change; change B had been planned but not started. It was run as an ODD feature instead ([feature document](../../odd/tasks/model-smoke-test.md)).
- **Recording tool callback.** Built a `ToolCallback` decorator that records each tool call: arguments, error flag and latency.
- **Scoring and report.** Built pure scoring logic (ADOPT, REJECT or PLAN_B) with a Markdown report.
- **Live smoke test.** Built a parameterized `@Tag("live")` test over 10 prompts, with the model chosen by `-Dkintsugi.model`.
- **Hardening (T2b), from review findings.**
  - A prompt that throws counts as a failed prompt.
  - A median latency above 60 s gives PLAN_B.
  - P7 must make 2 calls.
  - The test selects the tool callback by name.
  - The report prints the model and the temperature.
- **Candidate runs.** Pulled `qwen3:8b` and `qwen3.5:9b` and ran all three candidates.
  - All three got ADOPT: 8 of 8 valid positives, 2 of 2 negatives, 0 prompts threw.
  - Median latency per prompt: granite 14.3 s, qwen3 14.6 s, qwen3.5 34.9 s.
- **Model choice.** Wrote ADR-003 (`granite4.1:8b` default, `qwen3:8b` alternative) and updated ADR-006, `docs/setup.md` and the `repo-structure` spec.
- **Reviews.** Five native reviews (reliability lens), all approved and acknowledged. Offline suite: 37 tests green.

## Decisions and why
- **ODD instead of SDD for this change.** Why: the human's choice. The project `CLAUDE.md` still says SDD; this is an open question.
- **Adoption bar: at least 80% valid positives (7 of 8) and at least 1 of 2 negatives without a call.** Why: it closes the open question from session 02. Plan B stays below 50% (`docs/vision.md:237`).
- **English-only prompts, with two indirect ones instead of Spanish and Italian.** Why: Kintsugi works on English logs and incidents. Robustness to phrasing matters more than robustness to language, and the repo stays English.
- **The harness is in Java, not under `evals/`.** Why: the recording callback lives in the JVM. This is a smoke test of the Spring AI tool path, not a system eval.
- **Errors are detected by stripping a leading quote.** Why: `MethodToolCallback` JSON-encodes String results, so an error arrives as `"\"Error: ...\""`. A plain `startsWith` would count every error as valid.
- **A throwing prompt is recorded, not rethrown.** Why: rethrowing would fail a run that still meets the 7-of-8 bar.
- **Keep `granite4.1:8b`.** Why: it matches the others on validity and has the lowest latency. The test is saturated and does not rank the models, so the choice is revisited when the evals can tell them apart.
- **Feature-branch chain of three PRs.** Why: 721 lines for T1+T2 was over the 400-line budget. PR 2 (500 lines) is accepted over budget because half of it is tests.

## Decisions and why

- **C's threshold is a verification level set on dev** (ADR-030). The literal "L2/L3 failure" escalates 67% on dev, which would decide H3 by wording. No grid rule met both H3 conditions on dev. The human kept the pre-registered procedure, because changing it would only pick which condition fails.
- **The H1–H3 verdict procedure** (ADR-031):
  - one-sided case-level bootstrap p-values against each margin;
  - alpha 0.025, the reading of the vision's 95% CI;
  - intersection-union for multi-condition hypotheses;
  - Holm over {H1, H2, H3}.

  The vision states CI bounds, but Holm needs p-values.
- **Holdout coverage** (ADR-032):
  - D reaches 300 cases only with RE2-TT. D's real cost is about $0.0013 a case; an earlier $0.011 figure was the total of 9 lab cases, corrected in-session.
  - A reaches 200 cases only with holdout B.
  - Both became never-cut, so the M4 check cannot fail through a cut.
  - Holdout-2 runs 0, 0R, A and D.
- **The lab track in the pooled conditions.** H2a and H3a score the lab on the service only, so one metric is pooled.
- **TT's topology drops the seat→travel back edges** (ADR-033). The alternative, a cycle-tolerant `Topology`, would change the rules' ordering code three weeks before the freeze. The simplification hits D, 0 and 0R alike, so D − 0R stays fair.
- **RCAEval pseudo-cases kept, all 150** (ADR-034):
  - H2b on 15 lab controls was a switch: one extra false alarm by A gave p ≈ 0.26.
  - RCAEval records only 12 minutes before each fault, hence the 6 + 6-minute windows.
  - A's CPU commitment rises to about 67 hours, about 7 of M4's 20 nights.
  - H2c excludes the pseudo-cases, because their lighter dossiers would bias A's median in A's favour.
- **The holdout-read guard** (m4-gaps). The "read once" rule of ADR-015 is now enforced by the tools, not by notes.

# Journal — 2026-10-06 — Session 03: F1 by hand and lab observability

## What happened
- **F1 reproduced by hand.** The three services ran with two PostgreSQL containers. With 10 s of gateway latency, the order returned 201 `PAYMENT_PENDING` after 3.01 s. payment-service later stored an `AUTHORIZED` payment for that same order, so the order/payment inconsistency is now observed, not inferred.
- **lab-observability** ([feature](../../odd/tasks/lab-observability.md)):
  - ADR-008 and the lab-observability living spec.
  - Prometheus metrics in the three services.
  - An orders-by-status gauge `lab_orders{status}`.
  - Dockerfiles and `infra/compose.yaml`.
  - The Prometheus, Loki, Alloy and Grafana stack, with the "Lab — F1" dashboard.
  - `infra/scripts/verify-f1.sh`, which passes.
- **Reviews.** Every range was reviewed and approved. The reviews found real problems, all fixed:
  - the gauge took 120 s per scrape when the database was down;
  - a refresh could hang with no bound;
  - Grafana was reachable from the whole network with `admin/admin`;
  - the Docker socket risk was understated;
  - some docs overstated what the statement timeout guarantees.
- **A mistake.** A commit (`f155900`) went in with a failing test, because the verification chain read the wrong exit code. The race was fixed in `0edc7f5`. From then on the mvn exit code is checked before every commit.

## Decisions and why
- **Option A: Prometheus scrape plus Alloy reading Docker logs into Loki, with no traces or OTLP (ADR-008).** It is the smallest stack that makes F1 visible. PromQL and LogQL are the query APIs that the agent's M2 tools will use. Traces belong to the agent, and moving to OTLP later only adds to what exists.
- **Alloy instead of Promtail.** Promtail reached end of life on 2026-03-02.
- **A scrape never waits on the database.** The gauge serves a snapshot and refreshes in the background, single-flight. A failure is cached for the TTL, and nothing older than 10 s is served. Otherwise fault F4 would make order-service's metrics disappear: with the database down, one scrape took 120 s.
- **The 3 s statement timeout covers only the count query.** F4 must still be able to inject slow queries elsewhere.
- **Every host port is bound to loopback, and the Grafana password comes from an environment variable.** This is a local lab; the Docker socket in Alloy is root-equivalent, and that is accepted and documented.
- **Standing preferences from the user:** feature-branch-chain without asking; review consent always granted.

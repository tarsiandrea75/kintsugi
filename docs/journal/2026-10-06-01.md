## Decisions and why
- **ODD with living specs instead of plain ODD or SDD.** Plain ODD loses the readable contracts that the evals depend on (fault catalog, fault-injector, service APIs); SDD adds ceremony. Each feature now updates its spec in `openspec/specs/`.
- **Spring Data JDBC, not JPA (ADR-007).** Explicit SQL means an injected slow query is exactly the query that runs; ORM behaviour would blur the ground-truth cause.
- **Synchronous order → payment with explicit timeouts, no broker.** A timeout leaves the order in `PAYMENT_PENDING`, which is exactly the F1 symptom. A broker would add infrastructure and change the kind of fault.
- **No amount on payments yet.** Prices belong to the product catalog (F6); inventing them would be fake data.
- **The JDK `HttpServer` as the fake payment server, and `JdkClientHttpRequestFactory` for timeouts.** Neither adds a dependency or needs an ADR. `spring-boot-http-client` is not on the classpath in Boot 4.1.1 webmvc.
- **Unknown payment outcomes are documented, not fixed.** Reconciliation is a real feature. The inconsistency is also realistic material for the agent, so it will be planned with the fault injector.
- **Review scope.** Reviewing the full branch failed with `lens_context_budget_exceeded`. Reviews now run on each new range with `--base-ref`, and full-branch stop-hook candidates are not started once every range is reviewed.
- **A review finding was refuted.** Hibernate Validator 9.1.3's `@NotBlank` already uses `String.isBlank()`, so the reported Unicode-whitespace bug did not exist. The tests now lock in that behaviour.

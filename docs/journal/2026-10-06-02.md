- **Reviews:** every range was reviewed and approved, with lineages listed in the feature documents. Over the day the reviews found several real problems: Linux-only tests, thread starvation, a test that could pass without checking anything, and a weak gauge reference.

## Decisions and why
- **No database in gateway-mock.** It is a fake external system with nothing to persist. The ground truth about faults belongs to the future fault injector.
- **Gateway unavailable → 503 with nothing stored.** "Unavailable" is not a decline, so the order stays `PAYMENT_PENDING`. F2 (429) is decided later.
- **F1 timing.** The order → payment read timeout is 3 s and the payment → gateway read timeout is 15 s. With 10 s of latency, the order side times out first.
- **Virtual threads in gateway-mock.** Sleeping requests on platform threads could starve the admin API that the fault injector needs in order to restore the lab. With virtual threads off, a test reproduced it: 250 requests against 200 Tomcat threads.
- **Wait on an in-flight gauge, not a fixed sleep.** A time-based test can pass without checking anything. The gauge is also the F1 signal for Grafana.
- **PR 3 of the gateway-mock chain is a size exception (about 680 lines).** `HttpPaymentGateway` replaces the fake bean, so the change only builds and passes as one unit.
- **Reviews run per range with `--base-ref`.** Full-branch candidates exceed the reviewer context. The stop hook's full-branch START is not run once every range is reviewed.

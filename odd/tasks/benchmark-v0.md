# benchmark-v0

## Objective

Close M2 (vision §7): `docs/benchmark.md` v0 holds the lab holdout-1 table for Configs 0, A and D, with AC@1, Wilson 95% CIs and paired differences. One command regenerates it from committed results, and its plan is committed before the run. It passes whatever the local model scores.

## Problem

M2's measurements so far are dev results (`evals/results/2026-10-25-m0-dev/`, `2026-10-28-service-assessment-v1-v2-dev/`, `2026-10-30-config0-dev/`). Dev was read many times while the agent was built, so it cannot carry a claim. Holdout-1 has never been replayed.

## Why

A holdout read once, under a plan written before, is the first lab number that can be reported without the suspicion that it was chosen. Config 0 runs beside A and D, so the table shows what the LLM adds over the rules on the lab.

## Scope

- In: a pre-registered plan; the three holdout replays (0, A, D at the M0 settings: decision mode, `tables`, `plain`); the scored result; a `kintsugi_evals benchmark` command that renders `docs/benchmark.md` from committed result directories; `docs/benchmark.md` v0; the evals spec.
- Out: H1–H3 verdicts (they need RCAEval, M4); new configs (qwen3.5:9b is a separate dev experiment after this feature); any change to the agent or the rules.

## Constraints

- Holdout-1 is read once. A run that stops early is rerun whole for that config, and the plan says so in advance.
- The rules are frozen at `5797d16` (ADR-016, `evals/plans/2026-10-30-config0-dev.md`).
- The cloud run costs about $0.05 (15 samples), within the human's go-ahead of 2026-10-30.
- The local run takes about 1.5 h on this CPU.

## Design

- Branch `feat/benchmark-v0`, from `feat/rules-baseline` (`7c1efb4`) with `feat/service-assessment-close` merged (`1468e70`), so the rules route and every committed result are present.
- `kintsugi_evals benchmark --out ../docs/benchmark.md <result dir>...` reads each result directory's `scores.tsv`, `paired.tsv` and `inputs.tsv`, and writes one Markdown file: a header naming the command and the inputs' sha256, then per result a table of configs × faults (matches/n, AC@1, Wilson CI), coverage, and the paired rows. It computes nothing new: every number comes from the committed TSVs, so the document cannot disagree with them. A pure function from TSV text to Markdown, tested with pytest on fixture TSVs.

# Feature: eval-protocol, the measurement protocol and a stdlib scorer

## Objective

Make the protocol of `docs/vision.md` §6 concrete and executable:
- ADR-015 states how every run is planned, scored, compared and recorded;
- a Python scorer under `evals/` reads the replay driver's `summary.tsv` and prints AC@1 with Wilson CIs and paired differences with exact McNemar;
- the first committed result, M0 on `dev`, is reproduced by that scorer.

Follow-up feature 1 of `odd/tasks/vision-revision.md`, milestone M2.

## Problem

`evals/` is empty and every replay result is git-ignored. The numbers behind keep-or-revert decisions were computed by hand, without intervals, on 5 cases per fault. Nothing stops a plan from being written after the run.

## Why

H1–H3 are pre-registered (vision §1). Their verdicts need one deterministic, tested scorer and a recorded protocol before any holdout is read. Without it, M2's check (`benchmark.md` v0 regenerated by one command from committed results) cannot pass.

## Scope

In:
- `docs/adr/ADR-015-evaluation-protocol.md`;
- `evals/`: the `kintsugi_evals` package, its pytest tests, `requirements-dev.txt`, `plans/TEMPLATE.md`, the first `results/` entry and its retrospective plan;
- `openspec/specs/evals/spec.md`, the living spec of the scorer;
- `docs/concepts.md`: "Measuring an agent honestly";

Out:
- `docs/benchmark.md` (follow-up 4);

- RCAEval metrics AC@3, Avg@5 and the Brier score (follow-ups 6, 7, 9);
- any Java change.

## Design

- Package `evals/kintsugi_evals/`, Python standard library only, so a measurement runs with a bare `python3`. pytest is a dev dependency only, pinned in `evals/requirements-dev.txt`.
- Modules: `stats.py` (Wilson, exact McNemar, cluster bootstrap, Holm, the dev keep rule), `scoring.py` (TSV reading and the outcome rule), `cli.py` with `__main__.py` (`python -m kintsugi_evals score`).
- A case is keyed by (split, recording). A config is labelled by `--label NAME DIR`, else by the TSV's `route-mode-view`. A missing `view` column reads as `-`.
- Outcome of a row: on a fault, the reported cause equal to the truth on a COMPLETED run is correct, `UNKNOWN|UNKNOWN` is an abstention, anything else is a miss. On a healthy case, truth `NONE|NONE` (provisional until follow-up 10), `UNKNOWN|UNKNOWN` is correct and any cause is a false alarm.
- Output: printed report plus `scores.tsv`, `paired.tsv`, `report.txt` and a copy of each input `summary.tsv`, so a result regenerates from committed files.

## Acceptance criteria

1. `evals/.venv/bin/python -m pytest evals -q` passes, and was observed failing (RED) before the code existed.
2. Tests pin Wilson 95% 4/5 = [38%, 96%], 5/15 = [15%, 58%], 14/15 = [70%, 99%] and exact McNemar b=9, c=0, p = 0.00390625.
3. The cluster bootstrap gives the same interval for the same seed.
4. The healthy and abstention rule is unit-tested with synthetic rows.
5. The CLI on the two M0 replay dirs prints cloud 14/15 and local 5/15 pooled, their Wilson CIs and McNemar p ≈ 0.0039, and its output is committed under `evals/results/2026-10-25-m0-dev/` with a plan marked retrospective.
6. ADR-015 covers: plan template, Wilson, McNemar, cluster bootstrap, holdout read once, dev keep rule, healthy/abstention rule, Holm, `evals/results/`, stdlib-only and the pytest pin.
7. `openspec/specs/evals/spec.md` has requirements and GIVEN/WHEN/THEN scenarios for the scorer.
8. `.gitignore` ignores `evals/.venv` and not `evals/results/`.
